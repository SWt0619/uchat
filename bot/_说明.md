# Uchat AI 用户（聊天机器人）

方案：**外部进程 + 普通用户身份**接入（服务端**零改动**）。程序是 `chatbot.mjs`，用 **bun** 运行，**不需要任何第三方包**。

## 一、先填两样东西

| 文件 | 填什么 |
|---|---|
| `dsapi.txt`（或 `bot.pwd`） | **DeepSeek API key**（`platform.deepseek.com` 申请，形如 `sk-...`）。整行只放 key；两个文件都可，程序按 dsapi.txt → bot.pwd 顺序找 |
| `bot_config.json` | `admin` 改成**你自己的昵称**（默认 `RJL0619`）—— 只有这个昵称能下达切换指令 |

> 首次运行会自动用**注册码注册**一个用户（昵称取 `nickname`，注册码自动读 Uchat 根目录的 `invite.pwd`，你不用管）。

## 二、两种模式（你要求的）

| 模式 | 行为 |
|---|---|
| **`mention`**（默认） | **只在被 @ 时回复**（消息里出现 `@大肥鱼` 或 `大肥鱼` 都会触发） |
| **`ambient`** | **低频随机插话** ＋ 被 @ 时照常回复。频率由 `ambientChance`（每条消息触发概率，默认 0.04）与 `ambientMinGapMs`（两次随机插话最小间隔，默认 2 分钟）控制 |
| `off` | 完全闭嘴 |

**在聊天里切换**（只有 `admin` 昵称有效）：
```
@大肥鱼 切成 mention 模式      → 只在被 @ 时回复
@大肥鱼 切成 ambient 模式      → 低频随机插话
@大肥鱼 闭嘴                   → off
@大肥鱼 状态                   → 报当前模式与限额
```

## 三、怎么启动

- **随 Uchat 一起启动**：`稳定运行Uchat.bat` / `启动Uchat.bat` 里已加好自启（会等服务 8888 就绪再拉起 bot ✓）；也可单独双击 `start_bot.bat` ✓
- 日志：`bot\bot.log` ✓；bot 挂掉会自动重启（每 5 秒重试 ✓）

## 四、常用配置（`bot_config.json`）

| 键 | 含义 |
|---|---|
| `nickname` / `password` | bot 的用户名与密码 —— ⚠️ **密码只能包含字母和数字**（服务端注册分支的限制 ✓，带 `-`/`_` 会被拒） |
| `globalMinGapMs` | 任意两次回复之间的最小间隔（默认 8 秒 ✓ 防刷屏） |
| `maxPerMinute` | 每分钟最多回复次数（默认 6 ✓） |
| `contextMessages` | 带给模型的最近消息条数（默认 20 ✓ 越大越贵） |
| `maxChunkChars` / `chunkDelayMs` | 单条消息最大字数 / 切片间隔 —— **服务端限流 10 条/秒且超了静默丢弃**，所以长回答必须切片 ✓ |
| `persona` | 人设提示词（想让它话多/话少/毒舌都改这里 ✓） |
| `api.model` | 默认 `deepseek-flash`（= **DeepSeek-V4.1-Flash** ✓ 官方名）；换画风可用 `deepseek-v4-pro` |
| `api.baseUrl` | 默认 `https://api.deepseek.com`（OpenAI 兼容 ✓）；用阿里云百炼就换 `https://dashscope.aliyuncs.com/compatible-mode/v1` |

## 四之二、上下文与"记忆"（2026-09-25 改进）

原来只有内存里的滑动窗口，两个真问题：**① 重启就忘**（服务一重启/进程一挂，`history` 全清空）；
**② 不知道"自己刚说过什么"**（服务端不会把自己的消息回声给自己，而登录时的历史回放又被丢掉）。
典型症状：它说"我不吃芹菜"，下一句却回"你咋知道我不吃芹菜？"。

现在的做法：

| 机制 | 说明 |
|---|---|
| **历史落盘** | 每轮对话写入 `bot.history.json`（多实例按 `--base` 目录分开），启动时自动载入最近 N 条 ⇒ 重启不丢记忆 |
| **收下自己的话** | 登录/重连时服务端会回放历史（含自己说过的）⇒ 按 **assistant** 轮收进上下文 |
| **补齐也进上下文** | 断线期间漏掉的消息（`sync_result`）同样并入上下文，不再"中间断一下就断片" |
| **上下文锚点** | system 提示里显式写「**你（大肥鱼）最近说过：「…」**」「对方最近说：「…」」，模型不用自己从几十条里找 |
| **一致性规则** | 明确要求"与上文一致、**绝不能否认自己刚说过的话**"（原来那条"历史里已回答的绝不再重复"会诱导它否定自己） |
| 去重 | 回放/补齐会和本地记录重复 ⇒ 同昵称同内容（最近 6 条内）自动跳过，prompt 里不会出现两遍 |

调试：加 `--dump-prompt` 会把**最终发往模型的 messages** 写到 `<base>/bot.prompt.json`（含 system 与每一轮），
用来核对"上下文到底带上了没有" —— 自检脚本 `dev\_bot_context_test.js` 就是这么断言的（9/9 通过）。

> 仍然是**滑动窗口**（默认 30 条，`contextMessages` 可调）：没有跨天的长期记忆；要"记得上周说过的事"得再加一层摘要。

## 五、已知边界

- bot **只出现在聊天里**（会出现在在线列表 ✓），**不会进语音/视频通话** ✓（要它"说话"得另接 TTS ✓）
- 上下文是**滑动窗口**（最近 N 条 + 落盘 ✓，见第四之二节），没有长期记忆 ✓ —— 要"记得上周的事"需要再加摘要层 ✓
- 聊天内容会发送给模型服务商 ✓
- 服务端对你（以及 bot）有 **10 条/秒**的限流 ✓ 超了**没有报错**只是丢弃 ✓ —— 这也是为什么要切片 ✓

## 六、自检（不需要 key）

```
bun chatbot.mjs --mock-llm --selftest
```
会另开一个「测试同学」连接，向 bot 发一条 @ 消息，验证 **登录 → 收消息 → 触发 → 回复** 整条链路 ✓（用模拟回复 ✓ 不花钱 ✓）
